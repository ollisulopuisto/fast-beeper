Solmu 0.23.1 fixes the macOS DMG: it now ships the Beeper build again. 0.23.0's DMG was packaged in the inherited upstream (WhatsApp) mode, so a fresh install opened on the WhatsApp link screen instead of your Beeper setup. Existing data was never touched.

**Download:** see the assets below. The macOS build is universal (Apple Silicon and Intel), signed and notarized. Linux and Windows builds are unsigned.

## Since the last build (v0.23.0)

- **macOS DMG:** the notarized app is built in Beeper mode again (launcher, private Server tunnel and the existing `~/.zapfast-beeper-prototype` profile), matching the trial DMGs. The 0.23.0 DMG was the upstream WhatsApp client by mistake.
- **Compatibility:** the app honors the pre-rename environment names again: `ZAPFAST_PROFILE_ROOT` falls back for `SOLMU_PROFILE_ROOT`, and `ZAPFAST_BACKEND` for `SOLMU_BACKEND`, so older launchers and scripts keep working. (#175)

## Known limitations

- The in-app updater still tracks upstream ZapFast releases, not this repository's; update checks from this build will not see this release.
- Linux packages still install zapfast-named desktop/icon files alongside the solmu binary (upstream packaging fixtures); Solmu branding there is a follow-up.
- Windows builds ship unsigned (Azure Artifact Signing is not configured on this repository), and its MSI assets are still zapfast-named.
- The What's New tour test fails on the Windows and macOS CI legs (pre-existing since v0.22.0, hover-cue timing); Linux legs pass. Being investigated.
